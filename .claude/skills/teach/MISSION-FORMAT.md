# Formato do MISSION.md

`MISSION.md` fica na raiz do workspace. Captura o _motivo_ pelo qual o usuário está aprendendo este tópico. Toda decisão de ensino — o que ensinar a seguir, quais recursos apresentar, quais exercícios projetar — deve remeter a este documento.

## Modelo

```md
# Missão: {Tópico}

## Por quê
{1-3 frases. O objetivo concreto do mundo real que o usuário está buscando. O que muda na vida ou no trabalho dele quando tiver essa habilidade? Evite formulações abstratas como "para entender X" — busque o resultado subjacente.}

## Sucesso parece com
- {Uma coisa específica e observável que o usuário será capaz de fazer}
- {Outra coisa específica}
- {…}

## Restrições
- {Tempo, orçamento, compromissos anteriores, preferências de aprendizado, qualquer coisa que limite a abordagem}

## Fora de escopo
- {Tópicos adjacentes que o usuário explicitamente não quer buscar agora - protege a zona de desenvolvimento proximal}
```

## Regras

- **Uma missão por workspace.** Se o usuário quiser aprender duas coisas não relacionadas, isso são dois workspaces.
- **Concreto em vez de abstrato.** "Correr uma meia-maratona até outubro" é melhor que "ficar mais em forma". "Entregar uma CLI em Rust para o meu time" é melhor que "aprender Rust".
- **Questione a vagueza.** Se o usuário não conseguir articular o porquê, entreviste-o antes de escrever qualquer coisa. Uma missão ruim é pior do que nenhuma missão.
- **Revise quando a realidade mudar.** Missões mudam. Quando o objetivo do usuário se move, atualize este arquivo — não deixe uma missão obsoleta guiando sessões futuras.
- **Mantenha curto.** Se `MISSION.md` passar de uma tela, deixou de ser uma bússola e virou um plano.
